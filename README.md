# Ralph Loop: Autonomous AI Task Loops

Build autonomous coding loops where an AI agent picks tasks, implements them,
validates against backpressure (tests, builds), commits, and repeats — each
iteration in a fresh context window.

Uses the [GitHub Copilot SDK](https://www.npmjs.com/package/@github/copilot-sdk) (`@github/copilot-sdk`).

## Quick Start

```bash
# Install dependencies
pnpm install

# Run in build mode (default, 50 iterations)
pnpm start

# Run in planning mode
pnpm start:plan

# Run in build mode with custom iterations
npx tsx recipe/ralph-loop.ts 20

# Run in planning mode with 5 iterations
npx tsx recipe/ralph-loop.ts plan 5
```

## How It Works

A Ralph loop is an autonomous development workflow where an AI agent iterates
through tasks in isolated context windows. The key insight: **state lives on
disk, not in the model's context**.

```
┌─────────────────────────────────────────────────┐
│                   loop                          │
│  while iterations remain:                       │
│    ┌─────────────────────────────────────────┐  │
│    │  Fresh session (isolated context)       │  │
│    │                                         │  │
│    │  1. Read PROMPT.md + AGENTS.md          │  │
│    │  2. Study specs/* and code              │  │
│    │  3. Pick next task from plan            │  │
│    │  4. Implement + run tests               │  │
│    │  5. Update plan, commit, exit           │  │
│    └─────────────────────────────────────────┘  │
│    ↻ next iteration (fresh context)             │
└─────────────────────────────────────────────────┘
```

### Two Modes

1. **Planning** (`plan`): Reads specs, analyzes gaps, generates/updates `IMPLEMENTATION_PLAN.md`
2. **Building** (`build`): Picks tasks from the plan, implements, tests, commits

### Core Principles

- **Fresh context per iteration**: Each loop creates a new session — no context accumulation
- **Disk as shared state**: `IMPLEMENTATION_PLAN.md` persists between iterations
- **Backpressure steers quality**: Tests, builds, lints reject bad work
- **Start with PLANNING**: Generate the plan first, then switch to BUILDING

## Best Practices

1. Fresh context per iteration — that's the whole point
2. `IMPLEMENTATION_PLAN.md` is shared state between isolated sessions
3. Tests, builds, lints in `AGENTS.md` — the agent must pass them before committing
4. Start with PLANNING mode, then switch to BUILDING
5. Watch early iterations, add guardrails to prompts when the agent fails
6. If the agent goes off track, delete `IMPLEMENTATION_PLAN.md` and re-plan
7. Keep `AGENTS.md` brief — it's loaded every iteration
8. The agent runs autonomously with full tool access — use a sandbox
